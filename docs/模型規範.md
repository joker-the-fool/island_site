# RSL 島嶼 3D 建築模型規範　v1.3

給「用 AI 工具產生 3D 模型」的人。照這份規範做出來的 `.js` 檔，可以直接加進我們的島使用。
這份文件本身也可以整份貼給 AI 工具當作它的規格（第 13 節有現成的提示詞範本）。

---

## 0. 先搞清楚：交付的是什麼

- 交付物是**一支 JavaScript 檔案**（例如 `lemonade_demo.js`），用 three.js 的基本幾何（方塊、圓柱、球…）拼出低多邊形的小模型。
- **不是** `.glb`、`.obj`、`.fbx` 之類的模型檔。如果你的 AI 工具只能輸出這些格式，請改要求它「用 three.js 基本幾何寫成 JS 程式碼」。
- 一支檔案 = 一種「建築」（shape）或一種「島上人物」（character）。建築由多個「零件」拼成；零件寫在同一支檔案裡。
- 做好後，把檔案放進專案對應的資料夾並登記到 `manifest.js`（做法見第 12 節）：建築再指定給某座島使用，人物放在某座島的某個位置。

名詞：

| 名詞 | 意思 |
|---|---|
| 島（island） | 畫面上一座漂浮的小島，有編號、名稱、顏色、位置、橋 |
| 建築（shape） | 島上中央的那組主要模型（電影院、服務台…），每座島選一種 |
| 零件（part） | 組成建築的小東西（爆米花桶、熊、模特兒、旋轉招牌…），是檔案裡的一個函式 |
| 島上人物（character） | 站在島上的人（迎賓女服務員、推眼鏡的西裝男…）。獨立於建築，放在哪座島、什麼位置由資料決定 |
| 副島 | **就是一座島**：只是它的建築是「小島型建築」（燈塔島、泳池陽傘組島、自然小島…），位置、橋、大小都跟一般的島一樣在島編輯模式調整，不需要特別區分 |

## 1. 重點十條（先看這個）

1. 一支檔案登記一種建築：`ISLAND_SHAPES.<名稱> = { label, desc, themed, build(color, ctx) }`。
2. 整支檔案包在 `(function () { 'use strict'; … })();` 裡。
3. 零件**寫在自己的檔案裡**，不要依賴別的建築檔案，也不要被別的檔案依賴。
4. `build` 要回傳**一個** `THREE.Group`，不要自己 `scene.add`。
5. 原點在島中心的地面；`y` 往上；**正面朝 `+z`**。
6. 建議佔地 `x: -3.5 ~ 3.5`、`z: -2.8 ~ 3.0`，高度 ≤ 5.5。
7. 只用 `THREE` 與下列基本積木：`mat`、`mk`、`boxM`、`cylM`、`sphM`、`rng`。
8. 不要用網路、`eval`、`document`（除了 `document.createElement('canvas')`）、計時器、外部圖片。
9. 要動的東西用 `ctx.onUpdate(function (dt, t) { … })` 登記。
10. 做完把檔案放進 `shapes\`（建築）或 `characters\`（人物），並在 `manifest.js` 加一行，重新整理 `index.html` 看效果（第 12 節）。

## 2. 檔案怎麼組成島（架構）

```
index.html            頁面外殼
manifest.js           要載入的檔案清單（順序固定）
islands_data.js       島嶼資料：每座島的名稱、顏色、建築(shape)、位置、橋
shapes\<名稱>.js      一種建築一個檔案   ← 你交付的就是這種檔案
characters\<名稱>.js  一種島上人物一個檔案 ← 或是這種
js\、creatures\       主程式與生物（不用動）
maintain_tool.html    維護工具（編輯島、設定外觀與商場 LOGO）
```

運作方式：`islands_data.js` 裡每座島寫了 `shape: "名稱"`，頁面載入時依名稱找到 `shapes\名稱.js` 登記的建築，呼叫它的 `build(島色, ctx)` 取得模型，放到那座島上；每座島的 `characters` 欄位則列出島上要放哪些人物。

## 3. 座標、尺寸、朝向

- **座標**：`x` 往右、`y` 往上、`z` 往觀看者（正面）。原點是島中心的**地面**（不用管島本身的高度，系統會幫你抬到草地上）。
- **正面**：朝 `+z`。系統會自動把建築轉向，讓正面朝向中央的島，所以**不用管這座島放在哪裡**。門、招牌、擺飾都放在 `+z` 這一側；背面（`-z`）幾乎看不到。
- **單位與比例**：這是玩具風的小模型。參考：
  - 一般建築牆高 1.6 ~ 2.3，門約 0.9 寬 × 1.0 高。
  - 人物（含縮放）約 1.6 高，但仍比門高——這是刻意的玩具比例，不用追求寫實。
  - 小擺飾（杯子、熊、箱子）0.2 ~ 1.0。
- **佔地**（建議）：`x: -3.5 ~ 3.5`、`z: -2.8 ~ 3.0`。島的草地半徑約 4.3，超出會懸空。
- **高度**：非中央島建議 ≤ 5.5。島名標籤固定在島上方約 6.5 的位置，太高會擋到標籤。
- **鏡頭**：點島時鏡頭從正面前方約 16、上方約 13 的位置往下看，所以從**斜上方看正面**的效果最重要。

## 4. 建築檔案格式（shape）

### 4.1 骨架（複製這個開始寫）

```js
(function () {
  'use strict';
  // 建築：<中文名稱>（<一句話說明>）
  // 本檔案自成一體：用到的零件都放在這裡

  // ---- 零件（見第 5 節）----
  function somePartMesh() { const g = new THREE.Group(); /* … */ return g; }

  // ---- 建築 ----
  (window.ISLAND_SHAPES = window.ISLAND_SHAPES || {}).my_shape = {
    label: '中文名稱',          // 必填：顯示在維護工具的選單，建議 10 字內
    desc: '一句話說明',          // 建議：30 字內
    themed: true,                // 選填：true = 建築寬、擺飾多，島上周圍不種樹
    build(color, ctx) {
      const col = new THREE.Color(color), g = new THREE.Group();
      // … 用 boxM / cylM / sphM / mk 把東西 g.add(...) 進去 …
      return g;
    }
  };
})();
```

### 4.2 欄位

| 欄位 | 必填 | 說明 |
|---|---|---|
| `my_shape`（名稱） | 是 | 小寫英文、數字、底線，英文開頭，例如 `lemonade_stand`。**檔名要跟名稱一樣**（`lemonade_stand.js`）。一支檔案只能登記一種。 |
| `label` | 是 | 中文名稱 |
| `desc` | 建議 | 一句話說明 |
| `themed` | 否 | 預設 false。true 時島上周圍不種樹（範圍約 `x ±3.3、z ±2.8`） |
| `treeLeft` | 否 | true 時，原本會種在正面的樹一律改放到左邊（用在右側有擺飾的建築） |
| `treeBehind` | 否 | true 時，右側的樹改放到建築後方 |
| `build(color, ctx)` | 是 | 回傳 `THREE.Group` |

### 4.3 build 的參數

- `color`：這座島的主題色，字串（例如 `'#e0a040'`）。用 `new THREE.Color(color)` 轉成顏色。**只拿來做點綴**（屋頂、板子、旗子等）；其他顏色請自己決定，不要整棟都用島色。
- `ctx`：
  - `ctx.index`：這是第幾座島（從 0 起算，0 是中央島）。
  - `ctx.r`：島的半徑（一般島 5，中央島 5.8）。
  - `ctx.face`：建築被轉的角度（參考用，通常不需要）。
  - `ctx.onUpdate(fn)`：登記每幀要做的事，`fn(dt, t)`，`dt` 是這一幀經過的秒數，`t` 是總秒數。

### 4.4 小島型建築（副島）

副島不是特別的東西，**就是一座島**，只是它的建築用「小島型建築」。小島型建築是一般的建築檔案（登記在 `ISLAND_SHAPES`，放在 `shapes\`，檔名建議用 `isle_` 開頭），多宣告幾個欄位：

```js
(window.ISLAND_SHAPES = window.ISLAND_SHAPES || {}).isle_my_island = {
  label: '中文名稱', desc: '一句話說明',
  isle: true,           // 宣告這是小島型建築
  baseR: 2.5,           // 小島半徑（縮放 1 倍時），預設 2.5；之後用這座島資料的 scale 放大縮小
  sparse: true,         // true = 有擺設的小島，島上只放 2 株植物（石頭縮小）；false = 依半徑自動散布較多植物
  build(color, ctx) {   // 回傳放在島中央的擺設（THREE.Group）；原點在島中心的草地面
    return decorMesh();
  },
  arrange(plants) {     // 選填：重新安排植物位置（plants 是樹、棕櫚、灌木的物件清單，不含石頭；高度請設 0.5）
    plants.forEach((p, n) => { p.position.set(-1.5, 0.5, 0.4 - n); });
  }
};
```

與一般建築不同的地方：

1. 小島型的**島形、沙、草、浪花、植物由系統畫**，檔案只負責「中央的擺設」與「植物擺在哪」（自然小島連擺設都沒有，`build` 回傳空的 Group）。
2. 一般島的建築會自動轉向、正面朝向中央島；**小島型不會轉向，`+z` 就是朝向觀看者**。
3. 植物是樹、棕櫚、灌木、岩石混合散布（一般島只種樹）。
4. 這座島的資料可以把 `title` **留空**：不顯示標籤（編號與名稱都不顯示），副島預設這樣。
5. 其他規則（零件自成一體、禁止事項、效能上限）跟一般建築完全相同，收件時用同樣的方式檢查。

現有的小島型建築：`isle_lighthouse`（燈塔島）、`isle_pool`（泳池陽傘組島）、`isle_nature`（自然小島）。

## 5. 零件規範

零件 = 檔案裡的一個函式，回傳 `THREE.Group`。

1. **原點在零件底部中心**，`y` 往上，正面朝 `+z`。這樣擺放時只要設 `position` 就會貼在地上。
2. 命名：`xxxMesh(參數)`，例如 `lemonMesh()`、`cupMesh(顏色)`。
3. 可以帶參數（顏色、大小、變化），讓同一個零件重複使用。
4. **零件放在用到它的檔案裡，不要跨檔案共用。** 另一支建築要用同樣的零件，就複製一份過去。這是刻意的：改一個建築的零件，不會牽動別的建築。
5. 零件函式裡**不要**讀全域狀態、不要有副作用（不要 `scene.add`、不要改別的物件）。
6. 單一零件建議 ≤ 60 個 mesh。
7. 需要動畫的零件：回傳 Group 之外，把要動的子物件留在變數裡，由 `build` 用 `ctx.onUpdate` 去動它。例如：

```js
const sign = lemonMesh(); g.add(sign);
ctx.onUpdate(function (dt) { sign.rotation.y += dt * 1.2; });
```

零件擺進建築：

```js
const l = lemonMesh(); l.position.set(-0.5, 0.98, 0.3); l.rotation.y = 1.2; g.add(l);
```

## 6. 島上人物（character）規範

島上人物 = 站在某座島上的人（目前有「迎賓女服務員」、「推眼鏡的西裝男」）。**人物獨立於建築**：不綁定任何建築，放在哪座島、什麼位置由 `islands_data.js` 決定，同一種人物可以放在好幾座島。

### 6.1 檔案格式

放在 `characters\<名稱>.js`，格式跟建築類似，差別是登記到 `ISLAND_CHARACTERS`，而且 `build` **沒有 `color` 參數**：

```js
(function () {
  'use strict';
  // 零件：人物的身體（零件規範同第 5 節：自成一體、原點在腳底中心、正面朝 +z）
  function personMesh() { const g = new THREE.Group(); /* … */ return g; }

  (window.ISLAND_CHARACTERS = window.ISLAND_CHARACTERS || {}).my_person = {
    label: '中文名稱',            // 必填
    desc: '一句話說明',            // 建議
    build(ctx) {                   // ctx = { index, r, face, onUpdate(fn) }
      const p = personMesh();
      ctx.onUpdate(function (dt, t) { /* 每幀的動作，例如看 WALKERS 做反應 */ });
      return p;                    // 回傳 THREE.Group；位置與面向由資料決定，這裡不要設定
    }
  };
})();
```

### 6.2 規則

1. 原點在**腳底中心**，正面朝 `+z`；現有人物縮放後約 1.6 高（`root.scale.setScalar(1.5)`）。
2. `build(ctx)` 回傳**一個** `THREE.Group`；**不要**自己設定 `position`、`rotation.y`，由資料決定。
3. 人物的零件寫在自己的檔案裡，**不和其他人物、建築共用**（要用同樣的零件就複製一份）。
4. 要動的用 `ctx.onUpdate(function (dt, t) { … })`；可以讀 `WALKERS` 的位置做反應，**只能讀**。
5. 其他限制（禁止事項、效能上限、命名規則）同第 10 節，收件時用同樣的方式檢查。

### 6.3 放到島上（`islands_data.js` 的 `characters` 欄位）

```js
"characters": [{ "type": "hostess", "x": -0.7, "y": 0, "z": 3.1, "ry": 0 }]
```

| 欄位 | 說明 |
|---|---|
| `type` | 人物名稱，**必須是 `characters\` 裡已登記的名稱** |
| `x`、`y`、`z` | 相對於建築的位置，座標同建築：`x` 往右、`y` 往上、`z` 是建築正面。`y = 0` 是地面（建築若有台座，例如水泥台高 0.1，就設 `y: 0.1`） |
| `ry` | 面向角度（度）。`0` = 面向建築正面（`+z`）那一側，也就是朝向鏡頭／中央島 |

- 一座島可以有多個人物。因為座標跟著建築走，建築朝向中央島時，人物也會一起轉。
- 找不到的人物（名稱拼錯、檔案還沒放進專案）不會出現，頁面不會壞；維護工具會標示「無效」。

### 6.4 用維護工具放人物

「進入島編輯模式」→ 選一座島 → 側欄「島上人物」→「＋ 新增人物」→ 選種類、填 X／Y／Z／面向，或直接在鳥瞰圖上**拖動深色小圓點**移動位置（選取該島後才能拖）。

## 7. 島嶼規範

### 7.1 建築在島上的範圍與周圍

- 島本身（沙、草、浪花、標籤、橋、周圍的樹）由系統負責，**建築檔案不需要畫**。
- 島上周圍的樹是系統自動散布的；`themed: true` 的建築周圍約 `x ±3.3、z ±2.8` 不會有樹；`themed: false` 時樹可能出現在建築附近。
- 建築的**正面（`+z`）前方**，系統會避免擺樹，讓正面一目了然。
- 島與島之間用木橋相連，橋接在島的邊緣，建築不要放得太靠邊（`|x|`、`|z|` 超過約 4 會壓到橋與沙地）。

### 7.2 島嶼資料（`islands_data.js`）

每座島一個物件：

```js
{ "id": "entertainment", "title": "娛樂", "desc": "", "link": "", "color": "#d9744a",
  "shape": "cinema", "x": -13.9, "z": 10.9, "bridges": ["mall", "prestige"] }
```

| 欄位 | 說明 |
|---|---|
| `id` | 英文代號，小寫英文、數字、`-`、`_`，英文開頭，**不可重複**。網址加 `#id` 可直接飛到該島 |
| `title` | 島上標籤的名稱，建議 ≤ 8 個字；**留空就不顯示標籤**（副島用這個） |
| `desc` | 目前畫面沒用到，先保留 |
| `link` | 跳轉頁面（例如 `pages/data.html`）：先點島飛過去，再點一下已聚焦的島就跳轉；沒填就不跳 |
| `color` | 島的主題色，會傳給建築的 `build(color, …)` |
| `shape` | 建築名稱，**必須是 `shapes\` 裡已登記的名稱** |
| `x`、`z` | 島中心位置（場景單位）。`x` 往右、`z` 往下（往觀看者）。中央島固定在 `0, 0`；島的半徑約 5，兩座島中心距離建議 ≥ 10；範圍 ±48 |
| `bridges` | 用橋相連的島的 `id`，**兩邊都要列**（A 列 B，B 也要列 A），只會蓋一座橋 |
| `characters` | 這座島上的人物清單（見第 6 節）；沒有人物就是 `[]` |
| `scale` | 選填，預設 1。這座島整體的放大縮小倍率（島、建築、樹、人物一起縮放），建議 0.3 ~ 3；橋、重疊檢查、鏡頭都用縮放後的實際大小 |
| `seed` | 選填。島形與植物散布的亂數種子，同一個 seed 每次長出來都一樣。沒填就依這座島在清單裡的順序自動算（調整順序外形會跟著變）；填了就固定，不受順序影響。維護工具的「換個樣子」會隨機換一個 seed，「固定」會把目前自動算出的 seed 寫死（外形不變），「改回自動」會清掉 |

順序就是編號：第 1 個是中央島（建議放 `mall`），其餘依序放在四周。

這些通常**不用手寫**，用維護工具編輯（表格改名稱、顏色、建築；「進入島編輯模式」在鳥瞰圖拖動位置、調整大小、新增刪除島、設定連接、增減島上人物）。

### 7.3 新增一座島使用你的建築（完整流程）

1. 把建築檔放進 `shapes\` 並登記到 `manifest.js`（第 12 節）。
2. 「進入島編輯模式」→「＋ 新增島嶼」→ 拖到想要的位置（滾輪縮放、按住滑鼠中鍵拖動畫布）→「設定連接…」選橋 → 按「完成」。
3. 回表格，把新島的 `shape` 選成你的建築、改 `id`（英文）、`title`（中文）、顏色。
4. 要調整這座島的大小：回「進入島編輯模式」，選取該島，用側欄的「大小」滑桿（0.3 ~ 3 倍）。
5. 「儲存到檔案…」存回 `islands_data.js`，重新整理 `index.html`。

**新增一座副島**也是同樣的流程：新增島嶼 → 表格把 `shape` 選成「燈塔島／泳池陽傘組島／自然小島」（或自己做的小島型建築）→ `title` 留空 → 拖到想放的位置 →「設定連接…」選要連到哪座島（副島不再自動連到某座島，也不會跟著別的島移動，位置、橋都自己設）。

### 7.4 網頁外觀（`ISLAND_THEME`）與操作

`islands_data.js` 的最後有一段 `window.ISLAND_THEME`，設定首頁的外觀（建築、人物、副島的檔案**不需要**管這個）。用維護工具的「網頁外觀…」編輯，視窗裡有即時預覽：

| 欄位 | 說明 |
|---|---|
| `title`、`subtitle` | 左上角的標題與副標題文字；留空就隱藏 |
| `font` | 左上角文字的字型（空白＝預設；可用逗號列多個）。**顯示網頁的那台機器要有安裝這個字型才會生效**，沒有就退回預設字型（POS 是 Ubuntu，字型清單跟 Windows 不同） |
| `titleColor`、`subtitleColor` | 標題、副標題的文字顏色 |
| `primary` | 主配色：「全部小島」按鈕、縮放條（軌道與滑塊）、頂端橫條 |
| `secondary` | 副配色：縮放條的＋－按鈕、島嶼標籤的編號徽章 |

商場主塔正面的 LOGO **不放在這份資料裡**：用維護工具上方的「商場 LOGO」按鈕，先選一張 PNG、再按「生成LOGO資料」，工具會在專案資料夾產生 `logo_data.js`（`window.MALL_LOGO` = 圖的 data URL），網頁直接讀它，不需要另外放 PNG。發布時要把 `logo_data.js` 一併放進 ISLAND。

按鈕與徽章上的文字會依底色深淺自動用白字或深字。沒設定的欄位就用預設的樣式。

首頁的觸控操作（POS 觸控螢幕只有單點）：單指拖動＝旋轉；**輕點兩下、第二下不放開直接拖＝平移**（等同滑鼠右鍵拖動）；右上角縮放條＝縮放；單純雙擊不做任何事。因為雙擊的第一下也是點擊，「點島飛過去」會等約 0.35 秒確認沒有第二下才執行。

## 8. 可以用的東西

### 8.1 three.js

全域有 `THREE`（r160）。可以用的類別包含 `Group`、`Mesh`、各種 `*Geometry`（Box、Cylinder、Sphere、Cone、Torus、Icosahedron、Octahedron、Plane、Ring、Extrude、Tube…）、`CatmullRomCurve3`、`CanvasTexture`、`Vector3`、`Color`、各種 `Material`。

### 8.2 基本積木（`core.js` 提供，所有檔案都能用）

| 函式 | 作用 |
|---|---|
| `mat(顏色, 粗糙度=0.8)` | 低多邊形平面著色的材質 |
| `mk(幾何, 顏色, x, y, z)` | 用上面的材質建一個會投影的 Mesh，並設定位置 |
| `boxM(寬, 高, 深, 顏色, x, y, z)` | 方塊（`x,y,z` 是**中心**位置） |
| `cylM(上半徑, 下半徑, 高, 顏色, x, y, z, 邊數=10)` | 圓柱／圓台（中心位置） |
| `sphM(半徑, 顏色, x, y, z)` | 球 |
| `rng(種子)` | 可重現的亂數：`const rand = rng(42); rand()` 傳回 0~1 |

顏色一律用數字，例如 `0xffe14a`。

### 8.3 外觀風格

- 低多邊形、平面著色、飽和的暖色，跟現有建築一致。
- 要發光的東西（招牌、燈）用 `new THREE.MeshBasicMaterial({ color, toneMapped: false })`。
- 玻璃用 `MeshStandardMaterial({ transparent: true, opacity: 0.4 })`，少量使用。
- 貼圖只能用 `canvas` 在程式裡畫（見範例的 `stripeMat`），**不能讀外部圖片**；canvas 大小 ≤ 256×256，一支檔案最多 2 張。

### 8.4 讀取橋上小人的位置（選用）

全域陣列 `WALKERS`，每一項有 `p`（`THREE.Object3D`，用 `p.position` 讀世界位置）。可以讓建築或島上人物對走近的小人有反應（例如迎賓女服務員鞠躬、西裝男推眼鏡），**只能讀，不能改**。

## 9. 動畫

- 只能用 `ctx.onUpdate(function (dt, t) { … })` 登記，可以登記多個。
- 狀態放在自己的閉包變數裡。
- 每幀的運算要輕：不要在裡面建立新的幾何或材質，不要掃描整個場景。
- **不要**自己用 `setTimeout`、`setInterval`、`requestAnimationFrame`。

---

## 10. 禁止事項與上限

下面這些**不允許**（建築與人物檔案相同；收件時會依這份清單檢查）：

- `eval`、`new Function`、動態 `import(`、`importScripts`
- `fetch`、`XMLHttpRequest`、`WebSocket`（任何網路）
- `document.write`、`<script`、`localStorage`／`sessionStorage`／`indexedDB`
- `window.open`、`window.top`、`window.parent`、`window.location`
- 使用 `document`（只允許 `document.createElement('canvas')`）
- 一支檔案登記多種建築、名稱不合規、缺 `label`、缺 `build`、載入時就出錯
- 檔案超過 100KB

下面只會**警告**：沒有包在 IIFE 裡、沒有 `'use strict'`、缺 `desc`、檔案超過 30KB。

另外請遵守（工具查不出來，靠自律）：

- 不要加光源（燈光由系統統一設定）；不要改算圖器、鏡頭、場景；不要 `scene.add`。
- 一座建築總 mesh 數建議 ≤ 150；圓形邊數 ≤ 32（一般用 6~16）。
- `build` 要可重現：不要在建造階段用 `Math.random()` 決定形狀，需要變化就用 `rng(種子)`。
- 不要依賴其他建築檔案或它們的函式。

- [ ] 放進專案並登記後，重新整理 `index.html` 能看到模型，沒有出現錯誤訊息

- [ ] 有動畫的，動作順暢、不會一直增加物件
- [ ] 瀏覽器按 F12 的 Console 沒有紅色錯誤
- [ ] 附上一張預覽截圖和一句說明（`desc`）

## 12. 交付與放進專案

**交付**：一支 `<名稱>.js`（建築或人物，可附截圖）。

**放進專案（維護人員做，手動複製即可）**：

1. 建築檔放進專案的 `shapes\` 資料夾；人物檔放進 `characters\` 資料夾。檔名 = 檔案裡登記的名稱 + `.js`。
2. 用文字編輯器打開 `manifest.js`，在對應區塊加一行檔名：
   - 建築：加在 `'shapes/...'` 那一區，例如 `'shapes/lemonade_demo.js',`
   - 人物：加在 `'characters/...'` 那一區，例如 `'characters/waiter.js',`
   - 注意：一定要放在 `'js/island.js'` **之前**；每行結尾要有逗號（最後一行 `'js/main.js'` 除外）。
3. 專案裡已有同名檔案就是覆蓋；要保留舊的請先備份。
4. 重新整理 `index.html`，沒有錯誤就代表成功（有問題按 F12 看 Console）。
5. 建築會出現在維護工具的 shape 選單；人物要到「島編輯模式」的「島上人物」新增並擺位置。
6. 要發布時，把更新後的 `shapes\`、`characters\`、`manifest.js`、`islands_data.js` 複製到 `ISLAND` 資料夾。

## 13. 給 AI 工具的提示詞範本

把下面整段（連同這份規範）貼給 AI 工具，把【】處換成你的需求：

````text
請幫我寫一支 three.js (r160) 的 JavaScript 檔案，用基本幾何拼出一個低多邊形的玩具風小建築：【建築名稱與外觀描述，例如：「檸檬水攤：木頭攤車、黃白條紋遮陽棚、桌上有檸檬與杯子、頂上有一顆會轉的大檸檬招牌」】。

必須遵守（違反的檔案不會被接受）：
1. 整支檔案包在 (function () { 'use strict'; ... })(); 裡，最後登記：
   (window.ISLAND_SHAPES = window.ISLAND_SHAPES || {}).【英文小寫底線名稱】 = {
     label: '【中文名稱，10 字內】', desc: '【一句話說明，30 字內】', themed: true,
     build(color, ctx) { const col = new THREE.Color(color), g = new THREE.Group(); ...; return g; }
   };
2. 座標：原點在地面中心，y 往上，正面朝 +z。佔地約 x:-3.5~3.5、z:-2.8~3.0，高度 ≤ 5.5。主要特徵（門、招牌）放在 +z 這一側。
3. 只能使用全域的 THREE，以及這些函式（已存在，不要自己重寫）：
   mat(顏色, 粗糙度)、mk(幾何, 顏色, x, y, z)、boxM(寬, 高, 深, 顏色, x, y, z)、
   cylM(上半徑, 下半徑, 高, 顏色, x, y, z, 邊數)、sphM(半徑, 顏色, x, y, z)、rng(種子)。顏色用 0xRRGGBB 數字。
4. 小東西寫成「零件函式」放在同一支檔案裡，命名 xxxMesh()，原點在零件底部中心，回傳 THREE.Group。不要依賴其他檔案。
5. color 參數是這座島的主題色（字串），只用在少數點綴，不要整棟都用。
6. 動畫只能用 ctx.onUpdate(function (dt, t) { ... }) 登記；不要用 setTimeout / setInterval / requestAnimationFrame。
7. 禁止：eval、new Function、fetch、XMLHttpRequest、WebSocket、import()、document（除了 document.createElement('canvas')）、
   localStorage、外部圖片、自己加光源、scene.add、Math.random() 決定形狀（需要變化用 rng）。
8. 貼圖只能用 canvas 在程式裡畫（≤256×256，最多 2 張）。總 mesh 數 ≤ 150，圓形邊數 ≤ 32。
9. 風格：低多邊形、平面著色、飽和暖色。

輸出：只給一個 JavaScript 程式碼區塊（單一檔案），程式碼內用繁體中文註解說明各零件與各區塊，不要在程式碼之外輸出其他內容。
````

要請 AI 只做「零件」時，把需求改成「只寫一個零件函式 `xxxMesh()`，規則同上第 4 點」，再自己貼進建築檔案。

要請 AI 做「島上人物」時，用同一份提示詞，把第 1 點改成：

```text
1. 整支檔案包在 (function () { 'use strict'; ... })(); 裡，最後登記：
   (window.ISLAND_CHARACTERS = window.ISLAND_CHARACTERS || {}).【英文小寫底線名稱】 = {
     label: '【中文名稱】', desc: '【一句話說明】',
     build(ctx) { const g = new THREE.Group(); ...; return g; }   // 沒有 color 參數；不要設定 position / rotation
   };
   原點在腳底中心、正面朝 +z、縮放後約 1.6 高；要動的用 ctx.onUpdate(function (dt, t) { ... })，可以讀全域陣列 WALKERS（橋上小人，只讀）做反應。
```

要請 AI 做「小島型建築（副島）」時，用同一份提示詞，把第 1 點改成：

```text
1. 整支檔案包在 (function () { 'use strict'; ... })(); 裡，最後登記（檔名與名稱以 isle_ 開頭）：
   (window.ISLAND_SHAPES = window.ISLAND_SHAPES || {}).isle_【英文小寫底線名稱】 = {
     label: '【中文名稱】', desc: '【一句話說明】', themed: false, isle: true, baseR: 2.5, sparse: true,
     build(color, ctx) { const g = new THREE.Group(); ...; return g; },          // 島中央的擺設；原點在小島中心的草地面，+z 朝向觀看者（小島不轉向）
     arrange(plants) { plants.forEach((p, n) => p.position.set(x, 0.5, z)); }    // 選填：重新擺植物（樹、棕櫚、灌木）；沒有就不要寫
   };
   擺設佔地約在半徑 2.5 的 55% 以內、高度 ≤ 3；島的沙、草、浪花、植物由系統畫，不要自己畫。
```
